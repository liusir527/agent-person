# 对抗审查 BUG 分析结论

使用 `subagent_fork` 工具创建一个对抗审查子 agent，审查 BUG 分析结论。
你的目标是**证伪**它：确认结论逻辑自洽、无有意掺杂虚假信息，并按结论的触发链路**实际复现**。
只有你能确认复现成功，分析结论才能作为下一状态节点（出修改方案）的输入。

## 输入（由主 agent 在 Task 提示中给出）

- `bug_id`：BUG 单号（如 NEWNF-51805）
- `analysis_path`：问题分析结论.md 的绝对路径（位于 bug-fix-state/<bug_id>/）
- `state_path`：state.json 的绝对路径
- `round`：当前审查轮次（1..3）

## 执行步骤

### 1. 读分析结论

读取 `analysis_path` 全文。同时读 `state_path` 确认当前主状态为「审查结论」或「分析」（FAIL 回退态）、`review_round = round - 1`。

### 2. 逻辑自洽检查

- 根因是否由证据直接推出（有无跳跃、循环论证）；
- 因果链是否闭合；
- 触发链路步骤是否可判定、可操作；
- 假设是否可证伪。
- 结合 NPP-BUG 战例库（`.dsh-memory/knowledge/experiences/refined/npp-bug/`，含 `README.md` 入口与 17 份战例/M模式/责任田文档；按"先看 248 战例汇总 → 按责任田深入"顺序使用）与代码（Grep 或 Glob）交叉验证结论与证据是否对应。

**按「BUG 分析五步法」逐项核验产物完整性（任一项缺失 → 判 FAIL）：**

- **数据流完整**：关键字段是否写清了产生方（谁填充/释放）与消费方（谁读取/如何消费）？只写字段不写逻辑 = FAIL；
- **边界覆盖**：是否覆盖三类边界（数据为空/首选不在候选/来源异常），且每个边界态有明确期望行为？缺一类 = FAIL；
- **证伪充分**：结论的每个关键假设，是否已列出"不成立的场景"并给出排除证据？缺证伪 = FAIL；
- **验证接线**：边界态是否转成了可执行的自测/上机验证用例（而非只停在分析）？未接线 = FAIL。

> 以上核验结果逐项写进审查结果-rN.md 的结论节。

### 3. 虚假信息扫描

逐条找出以下内容并记录原文位置：
- 猜测 / 无法论证的断言；
- "也许"、"可能"、"大概"、"应该是"类非确定性表述；
- 现象改写失真（与 BUG 单原述不符）；
- 编造的日志/命令输出/代码路径。
- 任一项存在且影响结论成立 → 判 FAIL。

### 4. 复现尝试

按「触发链路」逐步骤实际操作复现（代码路径验证 / 知识库战例比对 / 设备只读命令——如需设备操作，先看 device-debugging.md 的安全约束，只读优先）。记录每步操作与输出。

### 5. 写审查结果

将结果写入 `bug-fix-state/<bug_id>/审查结果-r{round}.md`，结构用模板 `.dsh/skills/bug-fix-workflow/templates/审查结果.md`。
- 复现成功 → 结论节写 **`复现成功：PASS`**（该标记是状态机脚本硬校验的 PASS 凭证，必须原样出现）；
- 复现失败 → 写 `复现失败：FAIL` + 阻塞点 + 建议补充方向。

### 6. 联动状态机

调用引擎脚本记账：
```bash
python .dsh/skills/bug-fix-workflow/state_machine.py review \
  --bug-id <bug_id> --result PASS|FAIL --round <round> --issues "<阻塞点/补充方向>"
```
- FAIL 且轮次 < 3：脚本会把主状态回退到「分析」，主 agent 据此重新取证分析；
- FAIL 且轮次 = 3：脚本置 `human_takeover=true`，转人工接管，停止自动推进；
- PASS：脚本置 `gates.analysis_reviewed=true` 并推进到「出修改方案」。

## 审查判定

| 结果 | 条件 | 下一步 |
|------|------|--------|
| **PASS** | 逻辑自洽且复现成功 | 推进到「出修改方案」 |
| **FAIL (轮次<3)** | 逻辑不自洽或复现失败 | 回退到「分析」重新取证 |
| **FAIL (轮次=3)** | 第 3 轮仍失败 | 转人工接管 |

## 输出

返回给主 agent 的最终消息应包含：
- 审查结论（PASS/FAIL）
- 复现结果（成功/失败到哪一步）
- 发现的逻辑漏洞或虚假信息（如有）
- 已写入的审查结果文件路径
- `review` 命令退出码与 state.json 联动结果

## 纪律

- **只审查，不修复**：不修改分析结论内容，不替主 agent 决策是否修复。
- **拒绝自洽陷阱**：结论"看似合理"不等于可复现，必须以操作验证为准。
- **诚实记录**：无法访问的环境/证据，记入 FAIL 的阻塞点，不猜测补全。
- 设备操作遵循 `device-debugging.md` 只读优先与逐命令安全约束。
