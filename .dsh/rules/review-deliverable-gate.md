# 文档审阅交付物门禁（Review Deliverable Gate）

产出**文档类审阅交付物**（设计文档评审、问题清单、评审报告、BUG 单描述中引用原文的部分）时，必须遵守下面两条禁令。
两条都是"踩坑教训固化"，来自 2026-09-16 一次概要设计文档审阅：36 条批注中，对抗审查用机器比对揪出 6 处引文失真、1 处结论越界（误判"文档里不存在 §4.3.1"）。

## 禁令一：引号内的"原文如此"必须逐字命中

审阅文本里凡是**用引号包装成引用原文**的片段，必须能在原文中逐字命中（含标点、空格、全角半角）。

- 落盘前必须跑机器核验：抽出所有引号片段，逐个到原文全文做 `count()`，命中 0 的逐条分诊；
- 分诊规则：属于「原文引用」且未命中 → **必须改写**（改成原文真实语句）；属于「我的建议/术语/分级标签」 → 不需要命中，但措辞不得让读者误以为是原文（加"建议"前缀，或不用引号）；
- 典型翻车模式（实测全部命中）：**凭记忆改写**（原文"解析 DNAT 策略"→写成"不解析 DNAT 策略"）、**把需求当原文**（原文根本没写，却写成"原文要求读 X"）、**把表格两列拼成句子**、**自相矛盾**（批注 A 说"X 在正文无使用"，批注 B 锚的正是 X 的唯一正文出处）。

## 禁令二：断言"文档里没有 X"之前，必须做渲染态核对

**提取层的"看不到"不等于"原文没有"。** 纯文本提取会静默丢失四类信息，据此下否定结论会直接产出事实性误判：

| 盲区 | 提取层看到什么 | 会得出什么错结论 |
|---|---|---|
| 自动编号（`numPr`+`numbering.xml`） | 标题文本，看不到「4.3.1」 | "文档里不存在 §4.3.1" —— 实际该小节由 Word 自动编号生成 |
| 域（`TOC`/`PAGEREF`/`DOCPROPERTY`） | 静态数字 | "页码显示为域错误码" —— 域报错是渲染期产物，静态包里取不到 |
| 超链接内的 run | 段落有文字但 `paragraph.runs` 为空 | "该段没有可锚定的内容" —— 文字包在 `w:hyperlink` 里 |
| 批注 / 修订标记 | 正文文字完整 | "批注没加上" —— 标记不在正文流里，需单独核对 |

必须做到：

1. 先导出**渲染态**（如 Word COM 导 PDF），从 PDF **文字层**核对编号、页码、页眉页脚、目录的真实形态；
2. 与提取层**双向核对**；两者不一致本身就是一条缺陷（例如"目录标题与正文标题不符"）；
3. 断言写法必须区分"我没看到"与"不存在"：
   - 安全：「在纯文本层未命中，需渲染核对」「页码为域生成，其指向的标题已与正文不符」；
   - 危险：「原文不存在 X」「页码显示为域错误码」；
4. **优先级**：能用结构化/对象级证据回答的，不要走图像通道（图像结论依赖视觉通道可用性，且不可复现）。图像只用于"版面上有没有可见痕迹"这类文字层回答不了的问题；
5. 能力缺失（如模型不支持图像输入）**不得**被表述为"图里没有"。

## 强制力边界（如实声明）

- 禁令一可机械判定（字符串比对），**可实现为门禁脚本**；禁令二不可机械判定（依赖是否真去核对了），属**软约束 + 自审**；
- 本规则只约束**文档类审阅交付物**：代码审查、排障结论不在本规则范围（其引用适用各自的复核方式）；
- 违反后果：引文失真或否定性误判一旦被下游当作修改依据，会直接造成错误改动——按"文档误导"计，属 P1 级问题。
