# 任务边界与防扩散约束（analysis-only-workflow）

> 本文件是 bug-fix-workflow `references/task-boundary.md` 的 lite 版适配，**核心铁律一致**，仅去掉与 JIRA/上机验证/部署相关的条目。

## 1. 工作区边界（硬约束）

- 本次任务只允许修改**用户指定的仓库与工作区**；其余一律只读。
- 禁止为其他仓库创建 worktree / 分支 / 提交。
- 修改方案必须能落到本层代码；确需跨层改动时，先说明理由等用户确认，不自行展开。

## 2. 无 bug 单场景的特殊注意

- 没有 BUG 单号 → 不需要 JIRA 评论 / 状态流转 / PR 描述。
- 没有 PR 流程 → 编码完成后直接走 `代码审查记录.md` + `gate --flag code_reviewed --evidence`。
- 不强制上机验证 → 验证范围以边界态自测用例为主；如需上机请用户确认是否升级到 bug-fix-workflow。

## 3. 分层架构认知（与主线一致）

| 层 | 职责 | 常见问题形态 |
|---|---|---|
| WEB | 配置展示 / 下发 / 简单状态读取 | 界面显示、字段缺失、下发参数错误 |
| AGENT | biapi 封装 / 配置中转 / 数据搬运 | 字段透传、消息格式、api 同步 |
| VPP（npp） | 转发逻辑 / 选路 / 运行态数据 | 转发行为、选路结果、运行态字段 |

判断顺序同 bug-fix-workflow：先 VPP，再 AGENT/WEB。

## 4. 取证约束（证据够用为止）

- 不下载附件、不开浏览器、不做 OCR。
- 取证优先用代码阅读 + 现有日志；lite 流程下没有设备/编译机的强制依赖。
- 远程命令需要时用 ssh-tools / gdb-tools 等专用 skill，不自行拼凑。

## 5. 停止条件（每步自问）

> **这条信息会改变修改方案吗？不会就立即停止该方向。**

- 探索性工具（grep/read/CodeGraph）占用的上下文不算进度。
- 每完成一个取证动作，输出"结论：X；若此结论为假，方案是否受影响"，写不进这句话就停。

## 6. 自检清单（扩散警报）

出现以下任一信号 = 正在扩散，立即回退到任务边界：

- [ ] 创建了非本任务工作区的 worktree / 分支
- [ ] 在非工作区仓库里 grep / read 超过 3 次且没改变方案
- [ ] 下载附件、OCR、开浏览器查看与方案无关的内容
- [ ] 翻 WEB/AGENT 源码找"显示逻辑"而不是先在 VPP 运行态取证
- [ ] 反复读取同一批文件却写不出"结论 + 反证影响"
