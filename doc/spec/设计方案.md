# Agent 记忆系统设计方案

## 数字人永生计划

> **版本**: v1.0.0  
> **设计目标**: 构建一套零外部依赖、纯文本存储、可跨环境迁移的 Agent 记忆系统  
> **核心理念**: Markdown 文件是唯一真实数据源，SQLite 索引可随时重建


## 一、设计哲学

### 1.1 五大原则

| 原则           | 说明                                                    |
| :------------- | :------------------------------------------------------ |
| **明文真源**   | 所有知识只存于 `.md` 文件，人类可读写，Git 可版本管理   |
| **索引可重建** | SQLite 索引是 `.md` 文件的缓存视图，随时可删、可重建    |
| **零模型依赖** | 不依赖 embedding / LLM，所有检索基于关键词 + 结构化字段 |
| **指纹去重**   | 用确定性哈希（SHA-256）识别重复经验，避免知识库膨胀     |
| **跨环境迁移** | 整个目录 `git clone` 即恢复，无需任何外部服务           |

### 1.2 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    DSH Agent（运行时）                       │
│         每次会话启动时自动注入 PERSONA.md 摘要                │

└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      检索层（SQLite FTS5）                   │
│    关键词全文检索（BM25 排序）+ 结构化字段过滤                │
│    索引可随时从 MD 文件完全重建，零数据丢失                   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   存储层（纯 Markdown 文件）                  │
│    所有经验 = .md 文件，Frontmatter 结构化，正文自由         │
│    整个目录 = Git 仓库，可版本管理、可跨环境迁移              │
└─────────────────────────────────────────────────────────────┘
```

## 三、经验文件格式规范

每个 `经验.md` 文件必须包含标准 **Frontmatter**（YAML 格式）：

```markdown
---
id: exp-20260901-001
tags: [docker, network, bridge, troubleshooting]
severity: high                      # high | medium | low
category: error-pattern             # error-pattern | decision | config-tip
project: backend-service
occurrence: 1                       # 出现次数（去重后自动递增）
status: resolved                    # resolved | pending | deprecated
related: [exp-20260815-003]         # 关联的其他经验 ID
---

# Docker 网络配置坑

## 现象
容器内部无法访问宿主机 localhost，curl 连接失败。

## 根因
Docker bridge 模式下，容器内 127.0.0.1 指向容器自身，而非宿主机。

## 解决方案
使用 `--add-host host.docker.internal:host-gateway`

## 关键证据
报错信息: `curl: (7) Failed to connect to localhost port 8080`
```

### 3.1 字段说明

| 字段         | 类型    | 必填 | 说明                                        |
| :----------- | :------ | :--- | :------------------------------------------ |
| `id`         | string  | ✅    | 唯一标识，格式 `exp-YYYYMMDD-序号`          |
| `tags`       | array   | ✅    | 标签列表，用于分类和过滤                    |
| `severity`   | enum    | ✅    | 严重程度：high / medium / low               |
| `category`   | enum    | ✅    | 类别：error-pattern / decision / config-tip |
| `project`    | string  | ❌    | 所属项目名称                                |
| `occurrence` | integer | ✅    | 出现次数（自动维护）                        |
| `status`     | enum    | ✅    | 状态：resolved / pending / deprecated       |
| `related`    | array   | ❌    | 关联的经验 ID 列表                          |

### 3.2 正文章节约定

| 章节          | 必填 | 说明                             |
| :------------ | :--- | :------------------------------- |
| `## 现象`     | ✅    | 问题表现，用于全文检索和指纹生成 |
| `## 根因`     | ❌    | 根本原因分析                     |
| `## 解决方案` | ✅    | 具体的解决步骤                   |
| `## 关键证据` | ❌    | 错误日志、关键输出，用于指纹去重 |


## 四、索引层设计

### 4.1 SQLite 表结构

```sql
-- 主表：存储结构化元数据 + 指纹
CREATE TABLE experiences (
    id TEXT PRIMARY KEY,
    file_path TEXT UNIQUE NOT NULL,        -- 相对于根目录的路径
    tags TEXT,                             -- 逗号分隔
    severity TEXT,
    category TEXT,
    project TEXT,
    occurrence INTEGER DEFAULT 1,
    status TEXT,
    related TEXT,                          -- 逗号分隔的关联 ID
    content_hash TEXT NOT NULL,            -- 全文 SHA-256（检测文件改动）
    fingerprint TEXT UNIQUE NOT NULL,      -- 错误指纹（去重依据，唯一索引！）
    file_mtime INTEGER,                    -- 文件修改时间戳
    updated_at INTEGER                     -- 索引更新时间戳
);

-- FTS5 虚拟表：全文检索
CREATE VIRTUAL TABLE experiences_fts USING fts5(
    content,                               -- 现象+根因+解决方案+关键证据 拼接
    tokenize = 'porter unicode61'          -- 英文词干 + 中文分词
);

-- 关联表：主表与 FTS5 的映射
CREATE TABLE experiences_fts_content(
    id TEXT PRIMARY KEY,
    rowid INTEGER REFERENCES experiences_fts(rowid)
);

-- 索引：加速查询
CREATE INDEX idx_experiences_tags ON experiences(tags);
CREATE INDEX idx_experiences_severity ON experiences(severity);
CREATE INDEX idx_experiences_project ON experiences(project);
CREATE INDEX idx_experiences_occurrence ON experiences(occurrence DESC);
```

### 4.2 检索 SQL

Agent 调用 `memory_search(query, filters)` 时的核心 SQL：

```sql
-- 1. 结构化过滤（精确匹配）
WITH filtered AS (
    SELECT id, file_path, occurrence
    FROM experiences
    WHERE 1=1
      AND (? IS NULL OR tags LIKE '%' || ? || '%')
      AND (? IS NULL OR severity = ?)
      AND (? IS NULL OR project = ?)
),

-- 2. FTS5 全文检索（BM25 排序）
fts_matches AS (
    SELECT id, rank
    FROM experiences_fts
    WHERE content MATCH ?
    ORDER BY rank
    LIMIT 20
),

-- 3. 结果融合
combined AS (
    SELECT
        f.id,
        f.rank,
        e.occurrence,
        e.file_path
    FROM fts_matches f
    JOIN experiences e ON e.id = f.id
    WHERE e.id IN (SELECT id FROM filtered)
)

-- 4. 按 occurrence 加权排序
SELECT file_path
FROM combined
ORDER BY (1.0 / (rank + 1.0)) * (1.0 + LOG(occurrence)) DESC
LIMIT 5;
```


## 五、指纹去重机制

### 5.1 指纹生成算法（纯算法，零 AI）

```python
import hashlib
import re

def generate_fingerprint(content: str) -> str:
    # 1. 提取 "现象" 和 "关键证据" 章节
   现象 = extract_section(content, "现象")
   证据 = extract_section(content, "关键证据")
   error_text = 现象 + "\n" + 证据
    
    # 2. 规范化：去空格、转小写、替换变量（IP/端口/路径/数字）
    normalized = error_text.lower()
    normalized = re.sub(r'\d+\.\d+\.\d+\.\d+', '[IP]', normalized)  # IP 归一化
    normalized = re.sub(r':\d+', ':[PORT]', normalized)              # 端口归一化
    normalized = re.sub(r'\/[\/\w\-\.]+', '/[PATH]', normalized)     # 路径归一化
    normalized = re.sub(r'\b\d+\b', '[NUM]', normalized)             # 独立数字归一化
    normalized = re.sub(r'\s+', ' ', normalized).strip()             # 压缩空白
    
    # 3. 取前 200 字符 + 后 100 字符（抗局部变化）
    core = normalized[:200] + normalized[-100:]
    
    # 4. SHA-256 哈希
    return hashlib.sha256(core.encode('utf-8')).hexdigest()
```

### 5.2 去重流程

```python
def process_new_file(file_path):
    content = read_file(file_path)
    fp = generate_fingerprint(content)
    
    # 查重：走唯一索引，O(log N)
    existing = db.query(
        "SELECT id, file_path, occurrence FROM experiences WHERE fingerprint = ?",
        fp
    )
    
    if existing:
        # 重复经验 → 合并
        db.execute("""
            UPDATE experiences 
            SET occurrence = occurrence + 1,
                tags = merge_tags(existing.tags, new_tags),
                related = merge_related(existing.related, new_id),
                updated_at = ?
            WHERE fingerprint = ?
        """, (now, fp))
        # 不写入新文件，只更新统计
        return {"action": "merged", "into": existing.file_path}
    else:
        # 新经验 → 插入
        db.execute("INSERT INTO experiences ...")
        db.execute("INSERT INTO experiences_fts (content) VALUES (?)", body)
        return {"action": "inserted"}
```


## 六、增量更新机制

### 6.1 双保险检测逻辑（mtime + content_hash）

```python
def incremental_index():
    for md_file in glob("knowledge/experiences/*.md"):
        mtime = os.path.getmtime(md_file)
        
        # 1. 查数据库
        record = db.query(
            "SELECT content_hash, file_mtime FROM experiences WHERE file_path = ?",
            md_file
        )
        
        if not record:
            # 新文件 → 完整处理
            process_new_file(md_file)
            
        elif record.file_mtime != mtime:
            # 文件修改时间变了 → 读内容检查
            new_hash = sha256(read_file(md_file))
            if record.content_hash != new_hash:
                # 内容真的变了 → 更新索引
                update_existing_file(md_file, new_hash)
            else:
                # 只是 touch 了一下，内容没变 → 只更新 mtime
                db.execute(
                    "UPDATE experiences SET file_mtime = ? WHERE file_path = ?",
                    (mtime, md_file)
                )
        # else: 文件没变 → 跳过（不读内容）
```

### 6.2 文件修改后的更新流程

```python
def update_existing_file(file_path, new_hash):
    # 1. 重新解析 Frontmatter + 正文
    meta, body = parse_md(file_path)
    
    # 2. 更新 SQLite 主表（结构化字段）
    db.execute("""
        UPDATE experiences 
        SET tags = ?, severity = ?, category = ?, project = ?,
            status = ?, content_hash = ?, file_mtime = ?
        WHERE file_path = ?
    """, (meta.tags, meta.severity, meta.category, meta.project,
          meta.status, new_hash, os.path.getmtime(file_path), file_path))
    
    # 3. 更新 FTS5 全文索引（删除旧 + 插入新）
    db.execute("""
        DELETE FROM experiences_fts 
        WHERE rowid IN (SELECT rowid FROM experiences_fts_content WHERE id = ?)
    """, (meta.id,))
    db.execute("INSERT INTO experiences_fts (content) VALUES (?)", body)
    db.execute("""
        INSERT INTO experiences_fts_content (id, rowid) 
        VALUES (?, last_insert_rowid())
    """, (meta.id,))
    
    # 4. 重新生成指纹（如果核心内容变了）
    new_fp = generate_fingerprint(body)
    old_fp = db.query("SELECT fingerprint FROM experiences WHERE id = ?", meta.id)
    if new_fp != old_fp:
        db.execute("UPDATE experiences SET fingerprint = ? WHERE id = ?", (new_fp, meta.id))
```


## 七、性能基准

| 操作               | 文件数 | 耗时       | 说明                             |
| :----------------- | :----- | :--------- | :------------------------------- |
| 新增 1 个经验      | -      | **< 10ms** | 读文件 + 解析 + 指纹 + 写 SQLite |
| 合并 1 个重复经验  | -      | **< 5ms**  | 只 UPDATE，不写 FTS5             |
| 增量检测（无变化） | 1,000  | **~5ms**   | 只读 mtime，不读内容             |
| 增量检测（无变化） | 10,000 | **~50ms**  | 10,000 次 stat 调用              |
| 全量重建           | 1,000  | **~2s**    | 读全部文件 + 重建索引            |
| 全量重建           | 10,000 | **~20s**   | 一次性操作，仅在新环境执行       |

### 7.1 性能优化要点

| 优化策略               | 实现方式                         | 效果                        |
| :--------------------- | :------------------------------- | :-------------------------- |
| **批量提交**           | `BEGIN TRANSACTION` + `COMMIT`   | 多文件时写入次数从 N 降为 1 |
| **增量检测只读 mtime** | 不读内容，仅 `os.stat()`         | 10,000 文件仅需 50ms        |
| **指纹索引**           | `fingerprint` 字段加 UNIQUE 索引 | 查重 O(log N)，< 1ms        |
| **只更新变化字段**     | UPDATE 时只改变化的字段          | 合并时 < 5ms                |

hooks.on('session:start', async (ctx) => {

### 9.3 为什么索引要重建而不是复制 .db？

| 问题                | 说明                                       |
| :------------------ | :----------------------------------------- |
| **系统架构差异**    | SQLite 文件在 x86 和 ARM 间可能不兼容      |
| **SQLite 版本差异** | 不同版本 FTS5 存储格式可能有变化           |
| **确定性保证**      | 重建确保索引完全基于当前 MD 文件，无脏数据 |
| **文件路径变化**    | 新环境的工作目录可能不同                   |

## 十一、与 mem-gen 的工作流集成

```
[你完成一个任务]
        │
        ▼
[运行 mem-gen 生成经验总结]
        │
        ▼
[mem-gen 输出符合 Frontmatter 规范的 .md 文件]
        │
        ▼
[文件写入 ~/.dsh-memory/knowledge/experiences/]
        │
        ▼
[索引器自动检测到新文件（< 10ms）]
        │
        ├── 指纹查重 ── 命中 ──► 合并到已有记录（occurrence+1）
        │
        └── 未命中 ──► 插入 SQLite + FTS5 索引
        │
        ▼
[下次 Agent 遇到类似问题时，memory_search 能检索到]
```

**关键点**：`mem-gen` 只需做一件事——生成符合格式规范的 `.md` 文件。索引器完全自动消费，无需人工干预。

## 十四、总结

这套方案的核心价值在于：

1. **零外部依赖** — 不需要 embedding 模型、不需要向量数据库、不需要网络
2. **纯文本资产** — 所有知识是你能读懂、能编辑、能 Git 管理的 Markdown
3. **可迁移永生** — 整个目录带走，任何地方重建索引即可复活
4. **高性能** — 增量更新 < 10ms，10,000 条知识全量重建约 20 秒
5. **与现有工作流兼容** — `mem-gen` 生成的 md 文件直接纳入，无需改造
