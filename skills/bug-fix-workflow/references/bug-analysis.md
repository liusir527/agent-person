# BUG 分析

在处理 BUG 单或原始问题描述时使用本阶段。

## 有 BUG 单

1. 读取 BUG 描述、复现步骤、预期/实际结果、影响版本、设备型号、分支、附件和评论。
2. 将事实与猜测分开记录。
3. 把现象关联到代码区域、运行态模块、配置、流量路径或设备状态。
4. BUG 单信息不完整时，提出聚焦的反向问题，避免泛泛要求用户补充。

## 没有 BUG 单

1. 获取或推断最小可用问题描述：
   - 现象
   - 触发条件或复现步骤
   - 版本/分支/设备
   - 日志、崩溃、backtrace、报文方向或配置
2. 暂无运行态访问时，先从代码和知识库分析开始。
3. 只有需要运行态信息来验证或证伪假设时，才进入设备调试。

## 假设循环

维护按优先级排列的假设列表：

- 假设
- 支持证据
- 反证
- 下一步最低成本检查
- 所需工具或权限

优先选择能同时区分多个假设的检查动作。

## 计划门禁

满足以下任一条件前，不开始编码：

- 根因已知
- 代码路径已知且修复低风险
- 用户明确要求先给试探性补丁

仍不确定时，先输出诊断计划，再编辑代码。
