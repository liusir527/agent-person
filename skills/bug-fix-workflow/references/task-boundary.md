# 任务边界与防扩散约束（每次开工必读）

> 教训来源：NEWNF-54405 排查"SD-WAN 选路显示出口"时，主 agent 下载 JIRA 附件、OCR 截图、
> 为 web 仓库建 worktree、翻 Django serializer / Angular 组件——全部超出当前工作区（VPP/npp），
> 既没改代码也没推进问题，纯属扩散。本文件把"边界"固化为开工前置约束。

## 1. 工作区边界（硬约束）

- 本次任务只允许修改 **用户指定的仓库与工作区**（如 npp worktree），其余一律只读。
- 禁止为其他仓库创建 worktree / 分支 / 提交（包括 WEB、AGENT、vpp-agent 等）。
- 修改方案必须能落到本层代码；确需跨层改动时，先说明理由等用户确认，不自行展开。

## 2. 分层架构认知（决定"问题属于哪一层"）

本产品为三层架构，各层职责不同，问题归属按下列顺序判断：

| 层 | 职责 | 常见问题形态 |
|---|---|---|
| WEB | 配置展示 / 下发 / 简单状态读取 | 界面显示、字段缺失、下发参数错误 |
| AGENT | biapi 封装 / 配置中转 / 数据搬运 | 字段透传、消息格式、api 同步 |
| VPP（npp） | 转发逻辑 / 选路 / 运行态数据 | 转发行为、选路结果、运行态字段 |

判断顺序：
1. **先问"VPP 侧有没有这个数据/逻辑"**——转发、选路、运行态问题 90% 在 VPP 层闭环；
2. VPP 有数据但界面不显示 → 数据是否已通过 biapi 上报 → 才可能涉及 AGENT/WEB；
3. 显示类问题不要从 WEB 源码倒推，先在设备上确认 VPP 侧运行态（vppctl / CLI / show）。
4. 涉及 `*.api` 文件改动 → 编译通过后由本工作流**自动**执行 `vpp-api-sync` skill 暂存 api.json（约定动作，不需用户触发/提醒），不自行翻 AGENT 代码。
   - **强制自检**：暂存完成后必须 `--expect-field <新字段>` 校验通过，且本地 `runtime/<SESS>/<模块>.api.json` 必须真实落盘（grep 命中新字段），才允许在结论文档/汇报中声称"已移交"。
   - **防再犯教训（NEWNF-54405）**：sync_api_json.py 自动检测失败（打印"本地分支 = 空 / 未检测到 *.api 改动"）时，**不得**跳过或仅在文档中声称已暂存；必须用 `--api-file src/plugins/<模块>/<模块>.api --local-dir <本地worktree> --remote-worktree-name <worktree> --sess <SESS> --expect-field <字段>` 显式重试至成功。
5. 涉及 `*.api` 文件改动时的上机验证**退化为冒烟验证**：只检查 npp 能否启动、基础命令能否使用（`systemctl is-active pss-npp`、`vppctl show version`、`show pbr policy sdwan` 等），**不做全量配置/业务验证**——biapi 变更后 vpp-agent 未同步新 api.json 时无法经 WEB/AGENT 下发配置，全量验证属于交接项（vpp-agent 同步后由 WEB 侧回归）。
6. 需要配置类上机验证时实行**人机协作**：
   - agent 先输出 **测试方案.md**（测试场景、步骤、命令、预期结果、所需配置），提交给用户；
   - 由用户按方案在设备上完成配置（WEB / ssh），agent **不代行配置**；
   - 用户完成后，agent 按方案执行检查命令、比对预期、把结果记录到自测记录.md（记录谁执行、实际结果、与预期的差异）。

## 3. 取证约束（证据够用为止）

- 不下载附件、不开浏览器、不做 OCR。附件/截图不可读时，用文字描述现象请用户补充，不要绕路取证。
- 取证优先用设备只读命令（vppctl / CLI / show 命令）复现，而不是翻上层代码。
- 远程命令必须用 ssh-tools / gdb-tools 等专用 skill，不自行拼凑。

## 4. 停止条件（每步自问）

> **这条信息会改变修改方案吗？不会就立即停止该方向。**

- 探索性工具（worktree 派生、文件系统逐层翻找、跨仓库 grep）占用的上下文不算进度。
- 每完成一个取证/探索动作，输出一句"结论：X；若此结论为假，方案是否受影响"，写不进这句话就停。

## 5. 自检清单（扩散警报）

出现以下任一信号 = 正在扩散，立即回退到任务边界：

- [ ] 创建了非本任务工作区的 worktree / 分支
- [ ] 在非工作区仓库里 grep / read 超过 3 次且没改变方案
- [ ] 下载附件、OCR、开浏览器查看与方案无关的内容
- [ ] 翻 WEB/AGENT 源码找"显示逻辑"而不是先在设备上看 VPP 运行态
- [ ] **SSH 到设备/编译机读取非本层源码**（如 `grep/cat /opt/nsfocus/product/web/...`、`.../system/...`、
      `.../agent/...` 下的 py/js/配置文件）——**即使只读、即使为了"理解需求"也算扩散**；
      边界管的是取证动作本身，不是只管写文件
- [ ] 反复读取同一批文件却写不出"结论 + 反证影响"

> 教训来源：NEWNF-54251 主 agent 连续多轮 SSH 翻读设备 WEB 层源码（views.py/serializers.py/humansize.py）
> 试图倒推"显示单位"，把上下文烧在跨层取证上被用户叫停。显示/统计类问题一律先从 VPP 运行态
> （vppctl / /tmp/portraffic 等 npp 输出文件）取证；确需跨层理解时先停手问用户。
